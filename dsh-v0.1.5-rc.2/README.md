# dsh-ai-recorder

> AI 录音卡的 DeepSeek Harness 后端插件：蓝牙直连录音卡收音频 →
> 统一格式音频 → 语音识别（离线 / 实时）→ 以 `session_id` 为主键产出三件套，
> 并可把转写结果交给 Agent 整理成纪要。

适配内核：`@deepseek-ai/dsh` 0.1.5-rc 系列 ｜ 当前版本 `0.1.2-alpha.5`

---

## 它做什么

一块蓝牙录音卡（NextProto N0001 / CB08 · QS668）录完音，插件负责：

1. **BLE 直连**——扫描、连接、断线自愈，不需要装厂商 App
2. **离线同步**——把卡上的录音下载到电脑，边下边删卡（可选）、失败自动重试
3. **语音识别**——FunASR 或 Qwen3-ASR，支持离线整段与实时流式
4. **产出三件套**——一条录音一个目录：`音频 + Markdown + 实时文本流`，以 `session_id` 关联
5. **交给 Agent**——按提示词模板把转写发给指定对话，Agent 整理完可用工具把纪要挂回录音

---

## 界面

两个页面，**按可用宿主自动选择挂载位置**：

| 宿主 | 挂载方式 | 说明 |
|---|---|---|
| 装了 `dsh-whlab` | 工作台页面 | `录音卡后端` + `录音内容` 两个整页 |
| 没装 whlab | DSH 自带右侧边栏 | 注册成两个标签页 |

- **录音卡后端**——识别环境 / 运行配置 / 蓝牙直连 / 实时文本流 / 后处理选择
- **录音内容**——左侧录音列表，右侧详情（上播放器、下文档）。文档区分三个子标签：
  `转写原文` / `Markdown 文档` / `纪要查看`

选择逻辑是**严格回退**：有 whlab 就只用 whlab，没有才挂右侧边栏。

## 架构（五层）

```
┌─ L1 采集层 ────────────────────────────────────────────────┐
│  录音卡 ──BLE(AE20/GATT)──▶ scripts/ble_central.py         │
│    ├ 离线：文件列表 → 下载（.opus 优先｜16 kbps ≈ 2 KB/s）  │
│    └ 实时：TYPE=1 推流（40B/20ms 裸 Opus 包）              │
└────────────────────────────────────────────────────────────┘
                          │ 裸 Opus 包流
┌─ L2 预处理层 ──────────────────────────────────────────────┐
│  容器化：40B 裸包 → Ogg/Opus                               │
│  自检  ：前导污染探测 + 裁切（真机下载件前 ~4KB 非确定性）   │
│  解码  ：→ 16kHz / 单声道 / 16bit PCM（统一格式音频流）     │
└────────────────────────────────────────────────────────────┘
                          │ 统一格式音频
┌─ L3 识别层 ────────────────────────────────────────────────┐
│  scripts/funasr_worker.py（常驻进程，模型只加载一次）       │
│  scripts/qwen_worker.py（Qwen3-ASR，独立 venv）            │
│  预设：paraformer-zh / sensevoice / qwen3-asr              │
└────────────────────────────────────────────────────────────┘
                          │ 分段文本 + 说话人 + 时间戳
┌─ L4 输出层 ────────────────────────────────────────────────┐
│  一条录音 = 一个 session 目录                               │
│  音频（.ogg/.wav） + Markdown 转写稿 + 实时文本流           │
└────────────────────────────────────────────────────────────┘
                          │ session_id
┌─ L5 关联层 ────────────────────────────────────────────────┐
│  纪要文档（notes/<session_id>/<标题>.md）                  │
│  流转日志（flow-log.json：这条录音交给过谁、什么时候）       │
│  可读回「纪要查看」页                                       │
└────────────────────────────────────────────────────────────┘
```

## 快速开始

### 1. 安装插件

用 pm 系列工具热装，或写入 `cordis.patch.yml` 持久装配。

### 2. 装识别环境

打开「录音卡后端」→ 选一个 ASR 预设 → 点「安装 / 修复环境」。

插件会自动装 Python 依赖与模型（首次可能需要十几分钟，取决于网速）。

**环境按组件管理**，可以单独卸载：

| 组件 | 说明 |
|---|---|
| `funasr-py` | 系统 Python 中的 funasr / modelscope / torch 等 |
| `model-paraformer` | Paraformer-large 权重（约 850MB） |
| `model-paraformer-online` | 流式识别权重（约 850MB） |
| `model-sensevoice` | SenseVoiceSmall 权重（约 900MB） |
| `model-vad` | fsmn-vad 断句（约 4MB） |
| `model-punc` | ct-punc 标点恢复（约 1.1GB） |
| `model-spk` | cam++ 说话人分离（约 28MB） |
| `qwen-venv` | Qwen3-ASR 独立虚拟环境（约 5.3GB） |
| `qwen-models` | Qwen3-ASR 权重（约 4.5GB） |

**卸载是引用计数的**：一个组件被多个预设共用时，卸载其中一个预设不会删它；
只有最后一个用它的预设被卸载，它才会真正被删除。实例：

```
同时启用 paraformer-zh 与 sensevoice（两者共用 funasr-py / VAD / 标点 / cam++）
  卸载 paraformer-zh  →  只删 Paraformer 权重，共用组件保留
  再卸载 sensevoice   →  SenseVoice 权重 + 共用组件一并回收
```

### 3. 连设备

「录音卡后端」→ 扫描设备。**扫描会记住连过的设备并自动接回来**，
不需要每次从列表里挑。

连接后若开着「自动同步」，会把卡上的录音下载下来并识别。

### 4. 后处理（可选）

「录音卡后端」→ 后处理选择：

| 配置 | 说明 |
|---|---|
| **提示词模板** | 内置两套：`纪要整理`（按主题拆分多份文档）、`想法输送`（把录音当指令执行）。可另存为自定义 |
| **转向对话** | 发给哪个对话。默认「新建对话」，也可指定已有会话 |
| **运转方式** | `单次同步后自动流转` / `同步后手动确认再流转` |

**一轮同步 = 一条消息**：一次同步里有 5 条录音，会把 5 条转写**拼接成一份**再发送，
而不是发 5 条消息。

## 给 Agent 的工具

插件注册了一个工具，Agent 整理完纪要后调用它把成果挂回录音：

```
recorder_attach_notes
  sessionId  string   录音的会话 id（形如 session-…，在投放内容里给出）
  title      string   纪要标题，同时用作文件名
  markdown   string   纪要正文
```

调用后文档落到 `<数据目录>/notes/<录音会话 id>/<标题>.md`，
在「录音内容 → 纪要查看」里可读。**一条录音可以关联多份文档**
（一段录音讲了多个主题时，每个主题一份）。

内置提示词已包含使用说明：「只在对话里输出正文的话用户看不到，必须调用工具」。

## 录音内容页能做什么

- **多选**录音 → `删除选中` 或 `投放给 Agent`
- **投放**：选内容格式（转写原文 / Markdown 文档 / 纪要）+ 选提示词模板 →
  发给**当前打开的对话**（目标对话在按钮上方显示，会随你切换会话而变）
- **流转标记**：每条录音标明是否已交给过 LLM（总结 / 投放 / 自动流转都算），
  悬浮可见时间与目标对话
- **纪要查看**：列出 Agent 关联进来的文档

## 关键设计说明

### 为什么离线下载优先 `.opus`

设备里存的就是 **40 字节一包的裸 Opus**（20ms 一帧，约 16 kbps ≈ 2 KB/s）。
下载后本地容器化成 Ogg/Opus，**不做二次转码**——转码只掉质量不涨信息，
而且真机上转 WAV 会明显变慢。

### 为什么需要「前导污染自检」

真机下载件的前约 4KB 不是确定性内容，直接送进识别会产生幻觉文本。
所以下载后先探测污染区间并裁掉，再交给识别层。

### 识别层为什么是常驻进程

FunASR 的模型加载是秒级到十几秒级的开销。每次识别都起新进程的话，
短录音的耗时几乎全花在加载上。所以 `funasr_worker.py` 常驻，
模型只加载一次，之后走 stdin/stdout 的 JSON 行协议。

### 为什么「装没装」查 dist-info 而不是 import

判断一个 Python 包装没装，读 `site-packages` 里的 `*.dist-info` 目录即可——
毫秒级。早期版本是靠起进程真 `import torch` 来判断的，
一次 6 秒以上，导致界面上「FunASR 运行环境」长时间显示"检测中"。
用最贵的办法回答一个文件系统就能回答的问题，是设计错误。

### 为什么卸载要按引用计数

多个预设共享同一批组件。如果按"卸载预设就删它的组件"来做，
卸 A 会连带删掉 B 还在用的东西，B 就静默降级了
（比如删掉 cam++ 后，Qwen3-ASR 仍能跑但没有说话人标注）。

## 常见问题

**连不上 / 扫描不到设备**
先确认录音卡没被手机 App 占着。BLE 适配器同一时刻只能有一个扫描器，
插件内部对扫描/连接做了锁，但外部程序（厂商 App、系统蓝牙面板）抢了就会失败。

**识别很慢**
首次识别包含模型加载。之后常驻进程会复用已加载的模型。

**「已安装」但识别失败**
看「识别环境」里的依赖体检——包版本元数据在、`import` 却失败是最隐蔽的一种坏法
（典型是 `modelscope` 与 `modelscope-hub` 版本错配）。点「安装 / 修复环境」可修。

**装了 whlab 但想要右侧边栏**
当前是严格回退：有 whlab 就只挂工作台页面。需要右侧边栏的话卸载 whlab。

## 协议参考

BLE 帧格式：`MAGIC(0x5A) + SEQ(1B) + CRC16-XMODEM(2B LE) + LEN(2B LE) + [TYPE + CMD + PARAMS]`

CRC 覆盖 `LEN + DATA`；列表类整数为大端。

| 项 | 值 |
|---|---|
| Service | `0xAE20` |
| 写入特征 | `0xAE21` |
| 通知特征 | `0xAE22` / `0xAE23` |
